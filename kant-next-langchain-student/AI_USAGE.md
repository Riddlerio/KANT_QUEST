# AI 사용 기록

허용 범위는 개념 질문과 자신이 작성한 코드의 디버깅입니다. 과제 함수의 정답이나 전체 구현을 대신 생성하게 해서는 안 됩니다. 먼저 현재 단계 검사를 실행하세요.

사용하지 않았다면 아래에 사용하지 않았다고 적습니다. 사용했다면 질문마다 기록합니다. API 키, 개인 이메일, 실제 회사 데이터는 입력하지 않습니다.

# AI 사용 기록 작성용 메모

| 구분 | 질문 요약 | 공유한 자기 코드와 오류 범위 | 이해한 내용 | 직접 수정하고 검증한 결과 |
|---|---|---|---|---|
| 개념 질문 예시 | Document를 만들 때 본문과 metadata는 왜 나눠서 넣나요? | to_documents에서 Document를 만드는 부분 | 본문은 답변의 근거가 되는 내용이고, metadata에는 문서 ID나 출처처럼 문서를 구분하는 정보가 들어간다. | 두 값에 무엇이 들어가는지 직접 출력해 보고 결과를 적을 예정 |
| 개념 질문 예시 | for 앞에 식이 나오는 딕셔너리 컴프리헨션은 어떤 순서로 읽으면 되나요? | metadata를 만드는 딕셔너리 컴프리헨션 부분 | 반복문에서 키와 값을 하나씩 가져온 뒤 조건에 맞는 항목만 새 딕셔너리에 넣는 방식이다. | 작은 딕셔너리로 같은 문법을 연습한 뒤 결과를 적을 예정 |
| 개념 질문 예시 | sum 안에 숫자가 아니라 조건식이 들어가도 개수를 셀 수 있나요? | search_documents에서 키워드 점수를 계산하는 부분 | 조건식의 결과가 True면 1, False면 0으로 계산돼서 조건에 맞는 개수를 셀 수 있다. | 키워드가 들어간 경우와 없는 경우를 직접 비교해 볼 예정 |
| 개념 질문 예시 | 세션마다 InMemoryChatMessageHistory를 새로 만드는 이유가 뭔가요? | get_history에서 새 세션의 이력을 만드는 부분 | 세션별로 다른 객체를 보관해야 서로 다른 사람의 대화가 섞이지 않는다. 같은 세션에서는 기존 객체를 다시 사용한다. | 세션 두 개의 이력이 따로 쌓이는지 확인한 뒤 결과를 적을 예정 |
| 디버깅 | 출처가 정상인데도 중복이라는 오류가 나는 이유가 뭔가요? | validate_sources의 길이 비교 조건과 SourceValidationError | set은 중복을 없애므로 원래 목록과 개수가 다를 때 중복이 있다는 뜻이다. 비교 조건을 반대로 적으면 정상 출처를 거부하게 된다. | ==를 !=로 바꾸는 위치를 확인했다. 마지막 수정 후 검사 결과는 아직 기록하지 않았다. |
| 디버깅 | with_fallbacks를 호출했는데 AttributeError가 나는 이유가 뭔가요? | build_resilient_chain의 retry 대입문과 실패 복구 검사 결과 | 함수 호출이 끝난 뒤 쉼표를 붙이면 결과가 원소 하나짜리 튜플이 될 수 있다. 튜플에는 with_fallbacks가 없다. | 닫는 괄호 뒤의 쉼표를 지워야 한다는 걸 확인했다. 마지막 수정 후 검사 결과는 아직 기록하지 않았다. |
| 디버깅 | fallback을 보냈는데 왜 다음 생성이 또 시작되나요? | stream_answer의 오류 처리 부분과 스트리밍 검사 결과 | yield는 값을 보내고 잠시 멈추는 것이고, return은 함수를 끝내는 것이다. fallback 뒤에 return이 없으면 반복문이 계속될 수 있다. | fallback을 보내는 코드 뒤에 return을 추가했고, 다시 실행했을 때 스트리밍 검사는 모두 통과했다. |
